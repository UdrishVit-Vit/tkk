# План инфраструктуры сайта Эноа

Дата решения: 11 ноября 2026 года.
Обновлено 14 ноября 2026 года. Сайт enoa.club работает на Nuxt, NGINX и PostgreSQL 16.15.

## Действующий выпуск

Рабочий выпуск расположен в `/srv/tkk/releases/postgres-v1`. Служба `tkk` запускает его через ссылку `/srv/tkk/current`. Для следующей серверной сборки включить `TKK_POSTGRES=1`, установить зависимости через `pnpm install --frozen-lockfile` и выполнить `npm run build`. Передать на сервер также каталог `patches`. Поправка для db0 0.3.4 сохраняет знаки вопроса внутри материалов при импорте. Локальная сборка по умолчанию использует SQLite.

Приложение подключается через Unix-сокет к базе `tkk` от одноимённой системной роли. PostgreSQL слушает TCP только на loopback. Индекс содержит пять коллекций и 52 записи. Источниками для повторной сборки остаются файлы проекта.

Таймер `tkk-pg-backup.timer` создаёт дамп ежедневно в 03:00 UTC (06:00 МСК). Каталог `/var/lib/postgresql/tkk-backups` хранит дампы за 14 дней. Восстановление проверено через `pg_restore --exit-on-error --single-transaction` в отдельную базу со сверкой всех 52 записей. Копирование за пределы сервера предстоит настроить.

Для отката этого выпуска переключить `/srv/tkk/current` на сохранённый `/srv/tkk/releases/launch`, перезапустить службу `tkk` и проверить статью `/lore/names/udrishi`. Снимок исходного индекса сохранён в `/var/backups/tkk/launch-index.sqlite`.

## Согласованный стек

- Ubuntu Server 24.04 LTS — операционная система сервера.
- NGINX — HTTPS, выдача статических файлов и передача запросов приложению.
- PostgreSQL — выбранная серверная СУБД. Версию, схему и объём переноса данных определяем при подготовке миграции.
- Nuxt 4 и существующий сайт — сохраняем приложение, материалы и интерфейс.

Бюджетный ориентир: 1200 рублей в месяц. Провайдер и итоговая комплектация заказа ещё не зафиксированы.

## Требования продукта

- Аккаунты и сбор персональных данных не планируются.
- Планируется конструктор персонажей D&D 2014 и D&D 2024 с раздельными правилами редакций.
- Предлагаемый способ хранения персонажей: локально в браузере (IndexedDB), с экспортом, импортом и печатью. Реализация ещё не начата.
- Выбор PostgreSQL не меняет эти требования и не означает перенос персонажей на сервер.

## Текущее состояние и границы миграции

На сервере Nuxt Content использует PostgreSQL. Файловые справочники JavaScript/JSON и авторские тексты Markdown сохраняются в проекте.

Перед миграцией определить, какие данные остаются авторскими файлами, какие являются производными индексами, а какие должны храниться в PostgreSQL. Для каждой сущности определить основной источник данных; избежать ручного редактирования двух равноправных копий. Сохранить стабильные идентификаторы, ссылки и границы редакций правил.

## Исходный план работ от 11 ноября

1. Node.js поддерживаемой LTS-ветки и pnpm, совместимые с проектом; зафиксировать версии после проверки сборки.
2. systemd для запуска Nuxt после перезагрузки и перезапуска при сбое. Docker Compose пока не включён в согласованный стек.
3. Let's Encrypt и Certbot для HTTPS с автоматическим продлением и проверкой этого процесса.
4. Версионируемые миграции схемы PostgreSQL и проверяемый импорт данных.
5. Автоматические резервные копии PostgreSQL, материалов и конфигурации вне основного провайдера; отдельно сохранить роли и необходимые секреты с ограниченным доступом. Настроить срок хранения и регулярно проверять восстановление.
6. Внешняя проверка доступности сайта и уведомления; контроль свободного диска, памяти, ошибок приложения и выполнения резервного копирования. Ограничить размер и срок хранения журналов.
7. Повторяемая публикация: проверки, сборка, отдельный каталог новой версии, проверка работоспособности и сохранение предыдущей версии. Откат приложения должен учитывать совместимость схемы БД.
8. Базовая настройка доступа: SSH-ключи, отдельный пользователь приложения, сетевой экран, PostgreSQL без публичного доступа, секреты вне репозитория, обновления безопасности ОС.
9. Измерение загрузки страниц, оптимизация изображений и загрузки справочников, кеширование версионированных статических файлов; локальное размещение используемых шрифтов при соблюдении лицензий.

## Ресурсы и последовательность

8 ГБ памяти — предварительный комфортный ориентир для приложения и PostgreSQL на одном VPS. Потребление памяти и нагрузку необходимо измерить. Сборку предпочтительно выполнять отдельно от рабочего сервера; лимит памяти сборки 6 ГБ в package.json не является измерением потребления.

Сначала подготовить миграцию и резервирование, затем развернуть тестовый экземпляр, проверить страницы и запросы к PostgreSQL, выполнить пробное восстановление, после этого переключать домен.
