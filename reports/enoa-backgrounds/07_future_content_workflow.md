# Основа будущего процесса — этап E ещё не выполнен

Файл создан для соблюдения структуры ТЗ и фиксации требований. Это **рабочий проект процесса**, не стандарт, принятый по пилотам. `FUTURE_CONTENT_PROMPT.md` прочитан как будущие шаблоны задач; он не запустил создание нового контента в этом проходе.

1. Указать режим и редакцию: аудит / исправление / создание / адаптация / отдельная черта. Сначала поиск похожих существующих записей.
2. Сохранить baseline и договориться, что обязательно сохраняется в замысле. У разных редакций — разные механические записи.
3. Собрать Canon Brief: точная версия источника, локатор, эпоха, говорящий, авторский статус и природа свидетельства. Отделить PLAYER_SAFE от GM_FULL.
4. Определить социальную роль: работа, обучение, средства, заказчик, зависимость, запреты и личный выбор. Новые детали только PROPOSAL.
5. Собрать механический пакет редакции. Для 2014 не выдавать Origin автоматически; для 2024 выбрать допустимую Origin и проверить 50 зм в применимой модели.
6. У связанной черты проверить получение, предпосылки, действие, триггер, цель, дистанцию, длительность, ресурс, восстановление, масштабирование и сочетания. Два официальных аналога той же редакции/категории; отсутствие доступного источника явно отметить.
7. Редактировать текст: занятие в начале, конкретная причинность, без повторов и обязательного характера. Сохранить голос, не подгонять к единой длине.
8. Проверить данные и потребителей: ID, ссылки, стоимость, поиск, карточка, мобильное чтение; конструктор только если существует. Пройти реальные сценарии правила, не называть проверку полей playtest.
9. Провести независимое человеческое чтение и нужные игровые испытания. Зафиксировать замечания, затем получить авторское решение по лору, идентичности и существенному балансу.
10. Применить согласованный diff небольшой партией, проверить отсутствие потери данных и только затем публиковать при разрешении.

Предлагаемые стадии новых сущностей: DRAFT → RULES_REVIEWED → LORE_REVIEWED → PLAYTEST_READY → AUTHOR_APPROVED → PUBLISHED. Переходы подтверждаются доказательствами; уже существующие Legacy/Approved/Playtest не переименовывать миграцией без решения автора.

После этапа C этот проект процесса надо уточнить по пяти пилотам и отдельно принять. Сейчас никакая новая предыстория, обычная черта или Origin Feat не создана.
